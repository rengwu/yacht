## Question 26

```text
Round: Mockup round 3 decisions
Question: Should one 'Show accounts as: Icons / Labels' setting control both the menu bar and the dropdown?
Description (Markdown source):
You said entries must never mix icons and labels. With one setting:

| Setting | Menu bar | Dropdown headers |
| --- | --- | --- |
| Icons | Style 2: icon + % | Icon + label |
| Labels | Style 4: label over % | Label only |

Separate settings would allow, for example, labels in the menu bar and icons in the dropdown. That costs one more control.
Recommendation: One setting: it is the fewest controls, and the two surfaces always look consistent.
Options: One setting for both / Separate settings for menu bar and dropdown
Selected: One setting for both
Notes:
```

## Question 27

```text
Round: Mockup round 3 decisions
Question: What should the default for 'Show accounts as' be?
Description (Markdown source):
With icons, accounts from the same provider (Work and Home, both Claude) look identical in the menu bar, and only their order tells them apart. Labels avoid that and fit eight accounts beside the notch. Icons are narrower and quicker to scan when every provider appears only once.
Recommendation: Labels: your workload has several accounts per provider, and labels are never ambiguous. Icons stay one click away.
Options: Labels / Icons
Selected: Labels
Notes:
```

## Question 30

```text
Round: Mockup round 3 decisions
Question: How should a stale reading look in the menu bar?
Description (Markdown source):
A stale reading is a previous value kept after a refresh failed. In the dropdown, the values dim and a clock glyph shows the age (for example, 18m); the requirements say stale readings show their age. In the menu bar, the mockups currently only dim the figure.
Recommendation: Dim only: it adds no width, and the dropdown shows the clock and age when you look closer.
Options: Dim only / Dim plus a small clock glyph / No menu bar marker
Selected: Dim only
Notes:
```

## Question 31

```text
Round: Mockup round 3 decisions
Question: Should meters change colour when little usage is left?
Description (Markdown source):
The mockups use one accent colour for every meter. The earlier app had configurable warning and critical colour thresholds, but that is not an accepted requirement. Notifications are excluded; indicators stay visual.

| Option | Cost |
| --- | --- |
| One colour (system accent) | None; an empty meter already shows exhaustion |
| Fixed low colour (for example, orange under 10%) | No setting, but a built-in threshold |
| Configurable thresholds | Two more settings |
Recommendation: One colour from the system accent: it is the leanest, the most native, and the meter length already carries the signal.
Options: One colour (system accent) / Fixed low colour, no setting / Configurable thresholds
Selected: Configurable thresholds
Notes:
```

## Question 32

```text
Round: Mockup round 3 decisions
Question: Should the dropdown include 'Quit Yacht'?
Description (Markdown source):
The accepted dropdown actions are refresh and settings. Yacht has no Dock icon, so without a Quit item the only ways to quit are Activity Monitor or a Quit button placed in Settings.
Recommendation: Keep Quit in the dropdown: it is the standard place for a menu bar app, and it needs no extra window.
Options: Keep Quit in the dropdown / Move Quit into Settings / No Quit control
Selected: Keep Quit in the dropdown
```
